The problem

Phone orders still mean manual work.

Before

  • Repeat availability and price questions.
  • Open inventory to check stock.
  • Look up or create the customer by hand.
  • Write the order, then raise an invoice later.
  • Escalate a hard request by hunting for a person.
  • A missed call is often a missed order.

With Yuga

  • The caller speaks naturally on the merchant number.
  • Stock, price, and tax come from the live catalogue.
  • The incoming number links or creates the customer.
  • A confirmed quote can become a draft invoice.
  • A confirmed “speak to a person” starts a support transfer.
  • The merchant reviews the result in the existing billing app.

No market-size claims. This is the operational loop the current stack is built to shorten.

No invented middleware. ASR stays local. Provider mode uses Sarvam TTS. Local mode uses Kokoro. Only the LLM host changes with INFERENCE_MODE / LLM_PROVIDER.

INFERENCE_MODE

Same operations. Two inference hosts.

We did not reuse NODE_ENV. That already means development or production in Node. The switch is INFERENCE_MODE.

local

Merchant box

llama-server on :8081, Qwen3-0.6B. Nemo speech on :8080. Kokoro TTS in-process. If the local LLM is down, the call errors. It does not fall back to OpenRouter or Groq.

provider · default

Hosted LLM + Sarvam TTS

OpenRouter google/gemma-4-31b-it:free, with Groq still available via LLM_PROVIDER=groq. ASR stays local. Speech is Sarvam bulbul:v3 / priya. Keys come from .env.

Required: INFERENCE_MODE=local|provider · OPENROUTER_API_KEY or GROQ_API_KEY · SARVAM_API_KEY for provider TTS. Catalogue, customers, and invoices always use Mongo. They do not change with the model host. Paid OpenRouter models are refused.
